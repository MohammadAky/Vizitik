# پنل ادمین ویزیتیک

پنل مدیریت روی `admin.vizitik.ir` — شش بخش، همه با API واقعی سرور:

1. **داشبورد** — تعداد محصولات/سفارشات/مشتریان و **درآمد کل** (جمع مبلغ نهایی سفارش‌های لغو‌نشده) + نوار آمار جدول‌ها (کلیک روی هر جدول آن را در ادیتور SQL باز می‌کند)
2. **کوئری SQL** — ویرایشگر با اجرای `Ctrl+Enter`، تایید قبل از نوشتن، نمایش ساختار جدول، چهار زیرتب:
   - *ویرایشگر*: نتایج + نوار خروجی (CSV / JSON / **خروجی کامل** / کپی)
   - *قالب‌های آماده*: ۱۰ قالب آماده (کلیک → بارگذاری در ویرایشگر)
   - *تاریخچه*: ۱۰۰ کوئری آخر سمت سرور، شامل کوئری‌های ناموفق و پیام خطایشان
   - *ذخیره‌شده‌ها*: بوکمارک کوئری‌ها (ثبت/بارگذاری/حذف سمت سرور)
3. **محصولات** — افزودن/ویرایش/حذف، جستجو و فیلتر برند/دسته، صفحه‌بندی، **ورودی گروهی از CSV/JSON** و **خروجی CSV/JSON**، و دکمه‌ی «⚙️» روی هر ردیف برای **قیمت اختصاصی ویزیتورها**
4. **سفارشات** — فیلتر وضعیت/ویزیتور/بازه‌ی تاریخ، مشاهده‌ی جزئیات سفارش (اقلام و پرداخت‌ها)، خروجی CSV/JSON
5. **مشتریان** — فهرست با مانده‌ی حساب، فیلتر بدهکار/تسویه، پرش به سفارش‌های هر مشتری، خروجی CSV/JSON
6. **تنظیمات** — تایید قبل از نوشتن، نمایش ساختار جدول، حالت تاریک/فشرده، تعداد ردیف هر بارگذاری، فرمت و هدر پیش‌فرض خروجی، پاک‌کردن تاریخچه/بوکمارک‌ها

دکمه‌ی **«📤 خروجی»** در بالای پنل همیشه دیده می‌شود و از داده‌های همان بخشی که باز است خروجی می‌گیرد
(داشبورد → آمار جدول‌ها، SQL → نتیجه‌ی آخرین کوئری، محصولات/سفارشات/مشتریان → لیست همان بخش).

## ساختار
- `server.js` — سرویس Node کوچک (بدون وابستگی جدید؛ از Prisma Client بک‌اند استفاده می‌کند):
  - `GET /api/health` — بدون توکن، برای probe
  - `GET /api/tables` — فهرست جدول‌ها با تعداد دقیق ردیف
  - `GET /api/stats` · `GET /api/schema/:table` — آمار و ساختار جدول
  - `POST /api/query` — اجرای کوئری مجاز (`{sql, allowWrite, silent}`) با محدودیت خواندن/نوشتن
  - `GET|DELETE /api/query-history` — تاریخچه‌ی کوئری‌ها (موفق و ناموفق)
  - `GET|POST /api/query-bookmarks` · `DELETE /api/query-bookmarks/:id` — کوئری‌های ذخیره‌شده
  - `POST /api/export` — خروجی CSV/JSON از یک کوئری خواندن (تا `ADMIN_EXPORT_LIMIT`، پیش‌فرض ۲۰٬۰۰۰ ردیف)
  - `GET|POST /api/products` · `PUT|DELETE /api/products/:id` — محصولات سراسری (اگر فقط قیمت کارتن داده شود، قیمت واحد خودکار محاسبه می‌شود؛ حذف محصولِ فاکتورخورده با ۴۰۹ رد می‌شود)
  - `GET /api/user-products?productId=` · `PUT|DELETE /api/user-products/:userId/:productId` — قیمت اختصاصی هر ویزیتور برای هر محصول
  - `GET /api/users` — کاربران با آمار فاکتور
  - `GET /api/customers?q=` — مشتریان با مانده‌ی حساب و آمار فاکتور
  - `GET /api/orders?status=&visitorId=&customerId=&dateFrom=&dateTo=&limit=` — سفارش‌ها با اقلام و پرداخت‌ها
- `index.html`, `css/admin.css`, `js/admin.js` — رابط فارسی RTL با فونت Vazirmatn (از فونت‌های لندینگ سرو می‌شود)

## نکته‌های کار با داده
- هر `SELECT` در ویرایشگر سقف **۵۰۰ ردیف** دارد (سرور خودش `LIMIT` می‌گذارد). برای گرفتن کل داده‌ها از **«خروجی کامل»** استفاده کنید.
- ورودی گروهی محصولات، سرستون‌های انگلیسی (`name`, `brand`, `category`, `unitsPerCartonDefault`, `baseUnitPrice`, `cartonPrice`) و معادل فارسی‌شان را می‌پذیرد؛ ردیف‌های نامعتبر رد می‌شوند و در پایان گزارش می‌شوند.
- تاریخچه و کوئری‌های ذخیره‌شده در حافظه‌ی سرویس ادمین نگه داشته می‌شوند؛ با ری‌استارت سرویس صفر می‌شوند (دیتابیس دست نمی‌خورد).

## امنیت
- کل `/api/*` با هدر `X-Admin-Token` و مقدار `ADMIN_TOKEN` (در `backend/.env`) احراز می‌شود.
- توکن ادمین دسترسی قدرتمند خواندن/نوشتن دارد؛ آن را فقط به مدیر مورد اعتماد بدهید. محدودیت‌های SQL جایگزین کنترل دسترسی نیستند.
- حذف محصولِ فاکتورخورده مسدود است (۴۰۹) چون `OrderItem → Product` با Restrict به هم می‌خورد.
- LIMIT اجباری (۵۰۰) در ویرایشگر؛ هر LIMIT بزرگ‌تر خودکار به ۵۰۰ کاهش می‌یابد. خروجی `/api/export` تا `ADMIN_EXPORT_LIMIT` (پیش‌فرض ۲۰٬۰۰۰) مجاز است.
- در nginx روی دامنه ادمین هدرهای `X-Frame-Options: DENY`, `X-Content-Type-Options`, `Referrer-Policy` ست می‌شود.
- سرویس فقط روی `127.0.0.1:ADMIN_PORT` گوش می‌دهد؛ دسترسی از بیرون فقط از طریق nginx ممکن است.

## استقرار
`scripts/setup-server.sh` این پنل را کامل نصب می‌کند (ساب‌دامنه `ADMIN_DOMAIN`، پیش‌فرض `admin.$DOMAIN`، سرویس `vizitik-admin` روی پورت ۳۰۰۱، server block nginx و گواهی HTTPS). آپدیت‌های بعدی را `scripts/update.sh` (بخش `admin/` در diff) خودش جابه‌جا و سرویس را ری‌استارت می‌کند.

برای تغییر توکن روی سرور: `ADMIN_TOKEN=... ` را در `backend/.env` ویرایش و `systemctl restart vizitik-admin` را اجرا کنید.


## بدون بکاپ/بازیابی

پنل ادمین و اسکریپت‌های پروژه **بکاپ نمی‌گیرند و بازیابی نمی‌کنند**؛ اگر بکاپ می‌خواهی
روی سرور با `mariadb-dump` (یا `mysqldump`) بگیر و همان‌جا هم نگه ندار:

```bash
mariadb-dump --single-transaction --quick --skip-lock-tables -u vizitik -p hesabchin | gzip > ~/vizitik-$(date +%F).sql.gz
```

خروجی SQL پنل (`/api/export`) و خروجی CSV/JSON همچنان برای گرفتن گزارش است، نه بکاپ کامل.
تست واقعی MySQL/MariaDB عمداً جدا و opt-in است؛ راهنما را ببینید: [DEPLOY-UBUNTU](../docs/DEPLOY-UBUNTU.md).
